# 🚀 Explore With Me (Миграция на Spring Cloud)

Платформа **Explore With Me** помогает пользователям организовывать досуг: публиковать анонсы интересных мероприятий, управлять заявками на участие и находить компанию для совместного посещения событий.

В рамках текущего этапа дипломного проекта монолитное приложение переводится на рельсы микросервисной архитектуры. Основная цель — развернуть и связать инфраструктурные компоненты, которые подготовят проект к безопасному масштабированию в облачной среде.

---

## 🏗️ Архитектура и структура модулей

Проект реорганизован и разделен на логические блоки для удобного управления инфраструктурой и функционалом приложения:

### ⚙️ Инфраструктурный слой (`infra`)
Группирующий модуль для служебных сервисов экосистемы Spring Cloud:
*   **discovery-server (Spring Cloud Eureka)** — реестр, в котором динамически регистрируются все запущенные сервисы для последующего обнаружения друг друга.
*   **config-server (Spring Cloud Config)** — единый центр управления конфигурационными файлами, откуда сервисы запрашивают настройки при старте.
*   **gateway-server (Spring Cloud Gateway)** — центральный API-шлюз, принимающий все внешние запросы на порту `8080` и распределяющий их по целевым компонентам системы.

### 💼 Слой бизнес-логики (`core`)
Группирующий модуль, объединяющий основные сервисы платформы:
*   **ewm-service** — ядро приложения. Отвечает за регистрацию пользователей, ведение категорий, модерацию событий, фичу комментариев и обработку заявок.
*   **stats-service** — изолированный сервис для фиксации просмотров (содержит сервер сбора данных, DTO и клиентский модуль для интеграции).

---

## 🛡️ Отказоустойчивость и взаимодействие

*   **Динамический выбор портов:** Чтобы исключить конфликты при масштабировании, бизнес-сервисы запускаются на случайных свободных портах и автоматически передают свои координаты в Eureka Server.
*   **Умное обнаружение:** Связь между сервисом статистики и основным ядром переведена с жестко прописанных URL на использование `DiscoveryClient`. Адреса определяются на лету через реестр службы обнаружения.
*   **Политика повторных вызовов:** Интеграция клиента статистики защищена механизмом повторных запросов (`RetryTemplate`). Если сервер статистики не успел подняться или временно недоступен, клиент совершит до 3 автоматических попыток соединения с интервалом в 3 секунды.

---

## 🚦 Порядок локального запуска

Для корректной инициализации всех связей рекомендуется запускать модули в следующей последовательности:

1.  **discovery-server** — поднимает общую карту сети (порт `8761`).
2.  **config-server** — разворачивает службу конфигураций (случайный порт, регистрируется в Eureka).
3.  **stats-server** & **ewm-service** — загружают настройки из Config Server и регистрируют свои адреса в Eureka.
4.  **gateway-server** — активирует шлюз (порт `8080`), подтягивает маршруты и начинает проксировать внешний трафик к основному приложению.
